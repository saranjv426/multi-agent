ROOF DESIGN VALIDATION SYSTEM - HOW TO RUN

Project summary
===============

This project is a full-stack roof design validation tool.

Backend:
- FastAPI API server.
- Uploads image/PDF roof drawings.
- Extracts drawing panels from PDFs and images.
- Runs AI-assisted roof compliance validation.
- Supports authentication, password reset flow, database persistence, and PDF report generation.

Frontend:
- Next.js web app.
- Supports signup/login, upload workflow, model selection, validation results, and report download.


Prerequisites
=============

1. Install Conda or Miniconda.
2. Install Node.js LTS and npm.
3. Have an API key for the AI provider you plan to use.

Recommended local Python environment:

  conda create -n agent_env python=3.11 -y

If this machine already has the environment:

  conda activate agent_env

Backend setup
=============

From the project root:

  cd backend
  conda activate agent_env
  pip install -r requirements.txt
  cp env.example .env

Edit backend/.env and set the important values:

  OPENAI_API_KEY=your_openai_api_key_here
  OPENAI_API_BASE=https://api.openai.com/v1
  OPENAI_MAIN_MODEL=gpt-5
  OPENAI_SUMMARY_MODEL=gpt-5-mini
  JWT_SECRET_KEY=replace_with_a_long_random_secret
  HOST=127.0.0.1
  PORT=8000
  DEBUG=true
  ENVIRONMENT=development
  ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000
  LOCAL_DATABASE_URL=sqlite:///./local_dev.db
  ENABLE_SQLITE_FALLBACK=true
  FRONTEND_URL=http://localhost:3000

Optional provider routes are also available in backend/env.example:

  MISTRAL_API_KEY
  MISTRAL_API_BASE
  MISTRAL_MAIN_MODEL
  GPT52_API_KEY
  GPT52_API_BASE
  GPT52_MAIN_MODEL

Database note
=============

For production, set DATABASE_URL to PostgreSQL.

For local development, if PostgreSQL is not available, the backend can fall back to:

  backend/local_dev.db

This is controlled by:

  LOCAL_DATABASE_URL=sqlite:///./local_dev.db
  ENABLE_SQLITE_FALLBACK=true

Frontend setup
==============

Open a second terminal from the project root:

  cd frontend
  npm install

Create frontend/.env.local:

  NEXT_PUBLIC_BACKEND_URL=http://localhost:8000

Run the project
===============

You need two terminals.

Terminal 1 - backend:

  conda activate agent_env
  cd backend
  python start.py

Backend should be available at:

  http://localhost:8000

API docs should be available at:

  http://localhost:8000/docs

Terminal 2 - frontend:

  cd frontend
  NEXT_PUBLIC_BACKEND_URL=http://localhost:8000 npm run dev

Frontend should be available at:

  http://localhost:3000

Daily quick start
=================

Terminal 1:

  conda activate agent_env
  cd backend
  python start.py

Terminal 2:

  cd frontend
  NEXT_PUBLIC_BACKEND_URL=http://localhost:8000 npm run dev

Then open:

  http://localhost:3000

Testing
=======

Run backend tests:

  cd backend
  conda run -n agent_env pytest

Build frontend:

  cd frontend
  npm run build

Useful URLs
===========

Frontend:

  http://localhost:3000

Backend:

  http://localhost:8000

Backend API docs:

  http://localhost:8000/docs

Stopping the app
================

Press Ctrl+C in the backend terminal.
Press Ctrl+C in the frontend terminal.

Troubleshooting
===============

Problem: conda command is not found
Solution: Restart the terminal after installing Conda, or initialize Conda for your shell.

Problem: backend says the API key is missing
Solution: Edit backend/.env and replace placeholder API keys with real values.

Problem: frontend cannot connect to backend
Solution: Confirm backend is running at http://localhost:8000 and frontend/.env.local has NEXT_PUBLIC_BACKEND_URL=http://localhost:8000.

Problem: port 3000 or 8000 is already in use
Solution: Stop the existing process or change PORT in backend/.env. If the backend port changes, update frontend/.env.local too.

Problem: PostgreSQL is unavailable locally
Solution: Use the SQLite fallback settings shown above.

Problem: npm run build warns about caniuse-lite
Solution: This is a dependency data freshness warning, not a build failure. The current build passes.

Important details
=================

- Do not commit real .env secrets.
- Training Data contains sample PDFs/images used by tests and local validation.
- backend/local_dev.db is for local development only.
- PDF uploads may produce multiple drawing crops; each crop can be validated separately.
- Wall-section title extraction is preferred when a PDF sheet contains many details.
- start.sh is available as an interactive helper, but the two-terminal workflow above is the clearest local path.
